# Security evaluation

**Scope statement.** This repository contains RTL-level control-flow experiments and a *simulated*,
register-level leakage evaluation. It does **not** claim physical side-channel immunity of any
core. No oscilloscope, probe, EM or timing measurement of a routed device exists in this project;
routed-device measurements remain future work. Every statement below is limited to the evaluated
model, and the limitations are collected in Section 8.

Claim by claim, with the experiment that supports it, the exact script, and the generated result
(`results/json/*.json`, `results/csv/*.csv`):

## 1. Fixed execution cycle count (A)

*Claim.* Every evaluated input takes the same number of clock cycles from `start` to `done`.

*Evidence.* `tb/constant_time/tb_constant_time.v`, 256 vectors (16 directed corners including
all-zero and all-(q−1), 240 random) on the primary core (27 269 cycles), the pipelined-Barrett core
(30 853 cycles) and the per-phase reference (27 269 cycles). Reported as a unique-length count of 1.
`scripts/verification/ct_report.py` → `results/json/constant_time.json`.

*Why this is expected.* The multiplier-wait states leave on the registered `mult_done` flag, which
does not depend on operand values; the modular correction steps are comparator-selected
multiplexers, not branches. The exhaustive 2²⁴ Barrett test shows one correction always suffices.

## 2. Control-flow invariance (B)

*Claim.* The FSM state and every address-generating counter, the pass selector and the multiplier
start/done handshake follow the same trajectory for every evaluated input.

*Evidence.* The same testbench compares, at **every clock edge** of the run window, the control word
(FSM state, `target_sel`, `layer`, `len_reg`, `start_reg`, `j_reg`, `k_idx`, `bm_i`, `scale_idx`,
`mult_start`, `mult_done`, `done`) of each vector with that of vector 0, live, and also compares a
hash of the whole stream. Result for all 256 vectors on all three cores: 0 differing vectors.

A structural argument complements the test (every `if`/`case` in the FSM depends on `start`,
`rst_n`, `target_sel`, `mult_done` or an iteration counter; none inspects a coefficient), but the
repository relies on the simulation, not on the hand trace.

## 3. Memory-address invariance (C)

*Claim.* The sequence of coefficient-RAM read addresses and write enables/addresses is identical
for every evaluated input.

*Evidence.* Same testbench, address word: `a_ra0`, `a_ra1`, `b_ra0`, `b_ra1`, `mem_a_we`,
`mem_a_wa`, `mem_b_we`, `mem_b_wa` (write addresses masked to 0 when the enable is low, see
`docs/verification.md`). 0 differing vectors on all three cores.

*Negative control.* The data-carrying registers (`wa`, `wb`, `w_t`, memory write data) differ for
255/255 other vectors, so the comparison is able to detect data dependence.

> No data-dependent variation was observed in execution cycle count or memory-address sequence
> under the evaluated RTL control-flow model.

This is a statement about *schedule*. Combinational glitches, routing capacitance and physical
measurement effects are outside this experiment, and it says nothing about power or
electromagnetic leakage.

## 4. Simulated first-order leakage (TVLA)

All of this section is **pre-silicon simulation**, not physical power measurement.

| Item | Definition |
|---|---|
| Leakage model | per-clock-cycle Hamming distance between successive snapshots of every register the RTL declares: 35 fields for the shared-PE core, 47 for the per-phase core (three extra 4-field multipliers) |
| Model fidelity | `scripts/tvla/validate_model_vs_rtl.py`: every field equals the RTL value after every clock edge for one vector (940 051 / 1 267 279 values compared, 0 mismatches) |
| Trace | one sample per clock edge from the first edge after the start edge until the edge entering `S_DONE`: **27 268 samples** for a 27 269-cycle run (`docs/verification.md`, Section 4) |
| Groups | secret operand f **fixed** (seed 20260922) in the fixed group and uniformly random in the random group; the public operand g is uniformly random in both (a long-term secret meeting varying ciphertexts) |
| Traces | **400 per group** (main experiments); each group is generated by its own seeded generator: fixed 1001, random 2002, null groups 3003 and 4004 |
| Null test | two independent random-vs-random groups of 400 traces |
| Statistic | Welch's t per clock cycle, t = (m₀ − m₁) / √(s₀²/n₀ + s₁²/n₁), sample variances |
| Threshold | \|t\| > 4.5; expected false positives = (#evaluated cycles) · P(\|Z\| > 4.5) = (#cycles) · 6.8·10⁻⁶ |
| Undefined cycles | cycles whose Hamming distance has zero variance in both groups (control-only transitions; 3 076 of 27 268) have no defined t and are excluded |

Results (regenerated; `results/json/tvla_summary.json`):

| Configuration | max \|t\| | cycles with \|t\| > 4.5 | evaluated cycles | chance | null max \|t\| |
|---|--:|--:|--:|--:|--:|
| Unprotected shared-PE | 73.50 | 5 511 (22.78 %) | 24 192 | 0.16 | 4.50 |
| Unprotected per-phase reference | 73.50 | 5 511 (22.78 %) | 24 192 | 0.16 | 4.50 |

Both unprotected cores leak at first order in this model, as expected for an unprotected datapath.
The shared-PE and per-phase t-traces differ in only 6 of 27 268 cycles (0.022 %; largest
discrepancy 2.86), all in the first multiplier-wait state of a phase (`S_BM_M1W`, `S_INTT_MULW`,
`S_SCALE_MULW`). The mechanism is a property of the model: a gated-off multiplier retains its value
and contributes no switching, so the per-phase core's three idle multipliers are invisible to this
proxy, whereas the shared `prod_r` carries a value across each phase boundary. The result
therefore shows that sharing introduces no *additional register-level* leakage in this model; it is
not an independent measurement of equivalence.

**Five fixed secrets.** The manuscript repeats the experiment for "five independent fixed secrets"
at 200 traces per group and reports max \|t\| between 82.1 and 87.2 and 24.3 %–26.7 % of cycles
above threshold. Reproducing this showed that the original script
(`[random.Random(7000+k).randrange(q) for _ in range(256)]`) creates a **new generator for every
coefficient**, so each "secret" is a *constant polynomial* (all 256 coefficients equal 1320, 481,
2290, 2699 and 615). That version is reproduced bit-exactly (`multi_secret_constant_as_run`:
max \|t\| 82.05–87.23, 24.3–26.7 %). With five genuinely random fixed secrets
(`multi_secret`, the corrected experiment) the range is **49.8–69.3** and **21.8–22.3 %**. Both
variants are in the archive and the report; the manuscript sentence should be revised to describe
whichever experiment it intends to report.

## 5. Masking experiment

*Protocol (no RTL change).* By linearity of the NTT/INTT and bilinearity of the base
multiplication, with f = f₁ + f₂ (mod q) and f₁ uniform,

    core(f₁, g) + core(f₂, g)  ≡  core(f, g)  (mod q),

so the *existing* core is run twice and the two result polynomials are added **outside** the core.
Each run processes a polynomial statistically independent of f.

*Verification.* Model: 250 masked products against schoolbook, 0 failures. RTL
(`tb/functional/tb_masking.v`): 256 vectors × 3 invocations of the unmodified core, recombined
result = unmasked core output = golden product, 0 mismatches.

*Leakage (same methodology, 400 traces per group, seeds as in Section 4).* The two invocations form
a 54 536-sample trace (48 384 evaluated cycles): max \|t\| = **4.52**, **1** cycle above threshold
(0.33 expected by chance), null max \|t\| = 4.33. Latency overhead: 2.00× (54 538 cycles in RTL for
two invocations). Extra randomness: the 256 coefficients of f₁ per product.

*Reading.* This is first-order protection **under the evaluated register-level model**: no single
cycle's modelled activity depends on f, and the core never materializes the unblinded product.
Higher-order combinations of cycles, and glitch-extended leakage (transient recombination of the
two runs' data inside combinational logic or shared registers), are outside the experiment. Only
the operand that is split (f) is protected; g is not.

## 6. Shuffling experiment

*Construction* (`rtl/shared_pe/ntt_core_shared_shuffled.v`). Let L be the number of schedulable work
items of one list (L = 128 for each of the 7 layers of each transform and for the 128 base
multiplications, L = 256 for the scaling pass). The plain address incrementers are replaced by

    p₀ = start,   p_{i+1} = (p_i + stride) mod L,   stride forced odd,

a bijection on [0, L) because gcd(odd, 2ᵏ) = 1, so every item is visited exactly once. `start` and
`stride` come from a free-running 32-bit LFSR (x³² + x³⁰ + x²⁶ + x²⁵ + 1) at each phase/layer
entry. (L is used for the modulus to keep it distinct from the Barrett constant M = 5039.)
Layer order is not shuffled (layers are mutually dependent). NTT/INTT address decode from p:
`lg = 7 − layer` (NTT) or `1 + layer` (INTT), `gi = p >> lg`, `j = (gi << (lg+1)) | (p & (len−1))`,
`k = k_base ± gi`.

*Correctness.* Schedule equivalence for all 16 384 (start, stride) pairs; model (650 runs) and RTL
(6 LFSR seeds × 256 vectors, 1 536 runs) give the correct product with unchanged latency (27 269)
and unchanged multiplier issues (3 584); the model's unshuffled mode follows the original incrementing
schedule (same cycle count and issues). Seeds: 0xACE12345, 0x00000001, 0xFFFFFFFF, 0xDEADBEEF, 0x5A5A5A5A,
0x13579BDF.

*Cost.* The permutation state is `lfsr` (32), `p_idx` (8), `perm_stride` (8), `item_cnt` (9),
`k_base` (7) = **64 flip-flops declared**, plus a 7-bit adder and the address decode. These
registers are data independent and are **not** part of the leakage proxy.

*Leakage* (400 traces per group, LFSR seed drawn per trace): matched unshuffled control max \|t\|
73.26 with 5 530 cycles above threshold → shuffled **max \|t\| 6.34, 8 of 27 266** evaluated
cycles above threshold (0.19 expected by chance), null max \|t\| 4.09.

*Reading.* Shuffling is a **hiding** countermeasure. In this model it removes almost all
detectable first-order leakage at 400 traces, but 8 crossings exceed the 0.19 expected by chance,
so residual first-order dependence remains, and the protection degrades as the trace count grows
(an attacker needs more traces, not infinitely many). A constant or predictable LFSR seed voids the
countermeasure: the seed must come from a nondeterministic source at each power-up. The affine
permutation draws from far fewer orderings than a uniform shuffle; it retains the first-order
(single-cycle marginal) effect because each work item is equally likely to land in each time slot
(verified), but offers correspondingly less against attacks that combine several cycles.

## 7. Latency and area overhead

| | Latency | Hardware |
|---|--:|---|
| Unprotected | 1.00× | — |
| Shuffled order | 1.00× (27 269 cycles) | 64 declared flip-flops, 7-bit adder, address decode (mapped cost not part of the manuscript's area tables) |
| Masked, two runs | 2.00× | none in the core; recombination and randomness outside |

## 8. Limitations

1. **Simulation only.** No physical measurement. Simulated results do not establish resistance to
   any real measurement setup.
2. **Register-level model.** Combinational glitches, routing capacitance, supply and measurement
   noise are not modelled.
3. **First order, fixed-vs-random only.** No second-order, multivariate or profiled analysis.
4. **Masking** protects f only, needs fresh randomness, and its guarantee is for the evaluated
   register-level model; glitch-extended probing models and higher orders are not examined.
5. **Shuffling** is hiding, trace-count dependent, and needs a secret nondeterministic seed.
6. **Trace counts.** Results are for 400 traces per group; larger counts can reveal residual
   leakage that 400 traces do not.
7. **Exploratory variants** examined during development (random precharge, scalar multiplicative
   blinding) did not give a protection in this model and are not part of this release.
8. **Constant time** here means a fixed schedule and address trace in simulation; it is not a claim
   about the surrounding system, the technology mapping or physical timing.
