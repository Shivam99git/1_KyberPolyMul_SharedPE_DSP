# Architecture

This document describes the RTL in `rtl/`. Section numbers of the manuscript are not used; the
files named here are the ground truth.

## 1. Problem

Multiplication in the ring R_q = Z_q[x] / (x^256 + 1) with q = 3329 (CRYSTALS-Kyber / ML-KEM),

    h = f · g  =  INTT( NTT(f) ∘ NTT(g) ),

where `∘` is the base (pointwise) multiplication of the incomplete Kyber NTT.

* n = 256 coefficients, 12 bits each (0 ≤ coefficient < 3329).
* q = 3329 is prime, q − 1 = 2^8 · 13, so a primitive 256-th root of unity exists but a primitive
  512-th root does not. The NTT therefore stops one level early ("incomplete" NTT): **seven**
  radix-2 layers reduce R_q to 128 residues of degree 1, modulo (x² − ζ^(2·br(i)+1)).
* ζ = 17 is the primitive 256-th root of unity used (`scripts/common/kyber_ref.py` derives and
  checks it: ζ^256 = 1, ζ^128 = −1, and ζ^d ≠ 1 for every proper divisor d of 256).
* The transform operates on **n = 256 coefficients**; it is not a 128-point transform. The number
  128 appears in two places only: each of the seven layers contains n/2 = 128 butterflies, and the
  inverse transform's final normalization constant is `N_INV = 128⁻¹ mod q = 3303`, the
  normalization factor associated with the seven-layer incomplete transform (2⁷ = 128).

## 2. Computation phases and sequencing

One polynomial product runs five sequential steps; **no two overlap in time**:

| # | Step | Work | Multiplier issues |
|--:|---|---|--:|
| 1 | forward NTT of f (Cooley–Tukey, in `mem_a`) | 7 layers × 128 butterflies | 896 |
| 2 | forward NTT of g (Cooley–Tukey, in `mem_b`) | 7 layers × 128 butterflies | 896 |
| 3 | base multiplication | 128 coefficient pairs, 5 products each, result to `mem_a` | 640 |
| 4 | inverse NTT (Gentleman–Sande, in `mem_a`) | 7 layers × 128 butterflies | 896 |
| 5 | scaling by `N_INV` | 256 coefficients | 256 |
| | | **total** | **3 584** |

Because the steps are strictly sequential, at most one multiplier is ever active. The shared-PE
core therefore contains **one** modular multiplier, **one** modular adder and **one** modular
subtractor that every step time-multiplexes through operand multiplexers. The per-phase reference
core (`rtl/per_phase_baseline/`) replicates them (see `docs/baseline_definition.md`).

## 3. Datapath (`rtl/shared_pe/ntt_core_shared.v`)

```
          zeta_rom (twiddles)
              |
 mem_a ──┐    v                      ┌─────────── write-back
 mem_b ──┼─> w-regs ─> operand MUX ──┼─> MUL ─> w_t / w_m1 / w_za1b1 / w_a0b0 / w_a0b1 / w_a1b0
         │   (wa wb wc wd)   x6      ├─> ADD ─> add_y ─> mem_a / mem_b
         │                           └─> SUB ─> sub_y ─> mem_a / mem_b
```

* **Modular multiplier** (`mult_unit` → `mult_conventional`): a 12×12-bit integer product
  (one DSP48E1) registered in `prod_r`, then the Barrett reduction (`mod_reduce_barrett`, two
  further DSP48E1 for the constant multiplications ×M and ×q). Two clock cycles from issue to
  `result`; the FSM adds one handshake cycle, so a multiplier wait state lasts c = 3 clocks.
  This is why one multiplier uses 3 DSP48E1.
* **Barrett reduction** (`rtl/common/mod_reduce_barrett.v`), K = 24, M = ⌊2²⁴ / q⌋ = 5039:
  `t = (x·M) >> 24; r0 = x − t·q; y = (r0 ≥ q) ? r0 − q : r0`. One conditional subtraction always
  suffices (largest r0 over all 2²⁴ inputs is 5713 < 2q; `docs/verification.md`). The conditional
  subtraction is a comparator-selected multiplexer, not a branch.
* **Modular adder / subtractor** (`rtl/common/mod_addsub.v`): 13-bit add/subtract followed by a
  comparator-selected correction by q.
* **Operand multiplexers**: six in total, driven by the FSM state: multiplier operand A (4:1:
  `zrom_ntt_zeta`, `zrom_bm_zeta`, `wa`, `wb`), multiplier operand B (6:1: `wb`, `wc`, `wd`,
  `w_m1`, `w_diff`, `N_INV`), adder A (3:1) and B (4:1), subtractor A and B (2:1 each).
* **Memories**: `mem_a`, `mem_b`, each 256 × 12 bit, one write port and two **asynchronous** read
  ports, inferred as distributed LUT RAM (256 LUTs of "LUT as memory" for the pair, 0 BRAM). The
  asynchronous read is what keeps the design BRAM-free. `mem_a` also holds the final product and
  is read out through `read_addr` / `read_data` when the core is idle or done.
* **Twiddle ROM** (`rtl/common/zeta_rom.v`): `zetas_ntt.mem` (127 words, forward and — read in
  reverse order — inverse transform; the inverse needs no second table because the reverse-order
  factors equal −ζ⁻¹ of the forward ones) and `zetas_basemul.mem` (128 words), two asynchronous
  read ports. The image files are generated by `scripts/verification/gen_test_vectors.py`.
* **Top-level interface**: `clk`, `rst_n` (asynchronous, active low), `start` (one-cycle pulse),
  `done`, operand load port (`load_a_we`, `load_b_we`, `load_addr[7:0]`, `load_data[11:0]`) and
  result read port (`read_addr[7:0]`, `read_data[11:0]`). There is no top-level wrapper or I/O
  buffering: the cores are implemented out-of-context as standalone blocks.

## 4. Control FSM

38 states (`S_IDLE` … `S_DONE`). Every micro-sequence below ends in an `*_ADV` state that advances
counters (`j_reg`, `k_idx`, `layer`, `len_reg`, `start_reg` for the transforms, `bm_i` for base
multiplication, `scale_idx` for scaling) and selects the next micro-sequence. Branches depend only
on `start`, `rst_n`, the pass selector `target_sel`, the multiplier's `done` flag and those
counters; no state transition inspects a coefficient value.

| Micro-sequence | States per run S_x | Multiplier-wait states m_x | Runs |
|---|--:|--:|--:|
| Forward butterfly (LOAD, MUL, MULW, WB0, WB1, ADV) | 6 | 1 | 2·7·128 = 1792 |
| Base multiplication (LOAD, M1, M1W, M2, M2W, M3, M3W, WB0, M4, M4W, M5, M5W, WB1, ADV) | 14 | 5 | 128 |
| Inverse butterfly (LOAD, SUM, MUL, MULW, WB0, WB1, ADV) | 7 | 1 | 7·128 = 896 |
| Scaling (LOAD, MUL, MULW, WB, ADV) | 5 | 1 | 256 |

plus five single-clock states outside any micro-sequence: the four phase-init states
(`S_NTT_INIT`, `S_BM_INIT`, `S_INTT_INIT`, `S_SCALE_INIT`) and `S_DONE`.

Clock cycles from the start pulse to `done` (S_IDLE not counted), with c the multiplier wait length:

    N_cyc(c) = 5 + 2·S·(n/2)·[6 + (c−1)] + (n/2)·[14 + 5(c−1)] + S·(n/2)·[7 + (c−1)] + n·[5 + (c−1)],   S = 7, n = 256

* c = 3 (primary): N_cyc = **27 269** = 14 336 (forward) + 3 072 (pointwise) + 8 064 (inverse) +
  1 792 (scaling) + 5.
* c = 4 (pipelined Barrett): N_cyc = **30 853** = 16 128 + 3 712 + 8 960 + 2 048 + 5.

`scripts/verification/cycle_model.py` evaluates this expression and compares it with the cycle
count measured in RTL simulation; `docs/verification.md` defines the measurement.

## 5. Design variants

| Variant | RTL | Selected by | Multiply-reduce | c | Cycles |
|---|---|---|---|--:|--:|
| Primary shared-PE | `rtl/shared_pe/ntt_core_shared.v` + `mult_conventional.v` | default | 2 clocks | 3 | 27 269 |
| Pipelined Barrett | same core, `rtl/pipelined_barrett/mult_conventional_pipelined.v` | `USE_PIPELINED_BARRETT` | 3 clocks | 4 | 30 853 |
| Per-phase reference | `rtl/per_phase_baseline/ntt_core_baseline.v` | separate top module | 2 clocks | 3 | 27 269 |
| Shuffled issue order | `rtl/shared_pe/ntt_core_shared_shuffled.v` | separate top module | 2 clocks | 3 | 27 269 |

The **pipelined-Barrett** variant registers the intermediate quotient estimate `t_B` between the
two constant multiplications of the Barrett reduction (`mod_reduce_barrett_pipelined.v`), so each
DSP48E1 traversal lies in its own pipeline stage. Arithmetic is bit-identical; only the register
boundary moves. The control FSM is unchanged because its multiplier wait states loop on
`mult_done` rather than counting a fixed number of cycles.

The **shuffled** variant replaces the plain address incrementers by an affine permutation of each
phase's independent work list (`docs/security_evaluation.md`); it is not part of the area/timing
comparison.

## 6. File map

| Path | Content |
|---|---|
| `rtl/common/kyber_params.vh` | q, N_INV, Barrett K/M |
| `rtl/common/mod_reduce_barrett.v` | Barrett reduction mod 3329 |
| `rtl/common/mod_addsub.v` | modular adder and subtractor |
| `rtl/common/mult_conventional.v` | 12×12 product + Barrett, 2-cycle |
| `rtl/common/mult_unit.v` | multiplier selector (primary / pipelined) |
| `rtl/common/zeta_rom.v` | twiddle ROMs (`$readmemh` of `data/test_vectors/zetas_*.mem`) |
| `rtl/shared_pe/ntt_core_shared.v` | **primary top module** `ntt_core_shared` |
| `rtl/shared_pe/ntt_core_shared_shuffled.v` | shuffled-order top `ntt_core_shared_shuffled` |
| `rtl/per_phase_baseline/ntt_core_baseline.v` | per-phase reference top `ntt_core_baseline` |
| `rtl/pipelined_barrett/*.v` | pipelined Barrett stages and multiplier |

The top module for FPGA flows is `ntt_core_shared` (with `USE_PIPELINED_BARRETT` for the pipelined
core) or `ntt_core_baseline`. Twiddle ROM images are located through the macros
`ZETA_NTT_MEM` / `ZETA_BM_MEM` (default: relative to the repository root).
